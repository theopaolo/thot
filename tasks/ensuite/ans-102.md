## Diagrams

- [ ] Start with concept maps and simple process diagrams. Model output describes bounded nodes,
  relations and their evidence. Generate Mermaid syntax from the validated representation.
  Represent causal, chronological and thematic relations distinctly.
- [ ] Attach source references to factual nodes and relations. Keep proposed teaching connections
  labelled in both the diagram and its accompanying text. A valid diagram is not a verified claim.
- [ ] Use a pinned, locally bundled Mermaid renderer with strict security, HTML labels disabled,
  and no model-controlled directives, callbacks, links or external assets. Sanitize generated SVG
  before mounting it and test the chosen configuration against hostile fixtures.
- [ ] Bound diagram size and rendering work. Parse/render failure shows an accessible text or
  structured-list fallback rather than breaking the entire answer.

[Mermaid's configuration documentation](https://mermaid.js.org/config/usage.html#securitylevel)
describes the security modes. These settings are a starting point for qualification, not a
substitute for validating model output and testing the rendering boundary.

## Mathematics

- [ ] Qualify KaTeX for inline and display notation, including MathML output for accessibility.
  Use untrusted input mode, bounded expansion and size, and isolated macro state per render.
  Reject external resource and HTML-producing commands.
- [ ] Keep the original expression available as text. Rendering a formula does not validate its
  reasoning, units or result. ANS-101 owns those evidence requirements.
- [ ] Prototype fractions, matrices, Greek symbols, units and long equations with a sans-serif
  math configuration. Check required font assets and fallback glyphs against the project's font
  policy before enabling the feature. Preserve the existing font for interface and prose.
- [ ] Render failures keep the rest of the answer usable and provide the expression with a clear
  explanation. Long equations scroll within their own container.

[KaTeX options](https://katex.org/docs/options.html) document trust, expansion limits and rendering
configuration. Select and test an explicit safe configuration rather than passing model-provided
options through.

## Frontend and code touchpoints

Load the renderers only when a block requires them. Render completed blocks once after HTMX/SSE
updates. Cancel abandoned rendering and preserve scroll and focus. Use local assets instead of a
third-party rendering service.

## Acceptance

- [ ] Hostile SVG, Mermaid directives, oversized graphs, recursive macros and URL commands cannot
  execute scripts, fetch resources or freeze the page beyond the configured budget.
- [ ] Diagram text equivalents and mathematical accessibility are checked with keyboard and
  assistive-technology-oriented inspection.
- [ ] Each factual relation and formula can be traced to evidence or its explicit calculation.
- [ ] Helium screenshots cover long equations and diagrams on desktop and mobile.
