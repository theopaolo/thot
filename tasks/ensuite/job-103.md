## Backend

- [ ] Move generation initiation out of the SSE connection lifecycle. A submitted turn persists a
  job. A worker performs it. SSE or bounded polling reports durable progress and results.
- [ ] Extend the existing SQLite job approach with the required job types and lease ownership.
  Renew leases during long work and reject writes from a worker that has lost ownership.
- [ ] Separate interactive answer capacity from extraction/transcription capacity within the same
  instance. Use bounded workers or independent worker loops so a long recording cannot block chat.
  Avoid introducing a distributed queue for this deployment size.
- [ ] Preserve per-conversation ordering while allowing bounded concurrency across conversations.
  Enforce provider rate limits, per-account usage limits and configured instance concurrency.
- [ ] Persist progress before notifying clients. Reconnect by reading current state or replaying
  stored events. An SSE disconnect must not duplicate the work or cancel it implicitly.
- [ ] Implement explicit cancellation and bounded retries. Make output commits idempotent.
  A crash after a remote request may still cause a repeat provider charge unless the provider
  supports idempotency. Record attempts and expose that limit in operating guidance.
- [ ] Snapshot source/configuration revisions and recheck authorisation before result publication.
  Purging a conversation cancels its jobs and prevents late writes from recreating its content.
- [ ] Report queue time separately from provider processing. Preserve partial verified content
  only when its status and citations remain valid.

## Interface

Show queued, searching, generating, verifying, completed, cancelled and failed states using the
stages actually reported. Offer stop and retry where meaningful. Inactive conversations show
completion without moving focus or replacing the active conversation's content.

The same durable progress replaces the HTMX polling of ingestion progress in the teacher review
queue (formerly JOB-102).

## Acceptance

- [ ] A reply completes after leaving its page and appears when the conversation is reopened.
- [ ] Restart a worker, reconnect SSE and retry a request without duplicate result commits.
- [ ] A cancelled or expired worker cannot overwrite a newer job attempt.
- [ ] Run chat while a long media task is active and measure bounded interactive latency.
- [ ] Deleting or revoking access during processing cannot restore inaccessible content.
