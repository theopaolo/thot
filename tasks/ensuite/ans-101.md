## Answer contract

Introduce a versioned response representation with headings, paragraphs, lists, comparison tables,
procedural steps and source/media references. ANS-102 adds diagrams and mathematical notation.
Keep a reader for existing stored responses so migration does not require regenerating them.

Every factual statement carries references to accessible source revisions. An interpretation or
proposed teaching activity has an explicit label and cites the material that motivated it. A
labelled suggestion still cannot introduce invented source quotations or fabricated facts.

The verified claim stays the unit of evidence. An answered result gains an optional `blocs` array
that only arranges claims (`ranger()` in `src/core/reponse.ts`). The absence of `blocs` is the
reader for stored answers: they render as one paragraph, with no migration. Only the general
profile asks for blocks. The arts prompt keeps its measured fingerprint and its answers stay flat.

## Backend

- [x] Define a small discriminated set of content blocks with bounded length, nesting and count.
  Validate all model output and resolve source identifiers against the retrieved, authorised set.
- [x] Preserve exact quotation checks and add support verification appropriate to multi-source
  comparisons. Verify each side separately, then the relation being asserted. Do not treat two
  individually true statements as proof of a causal connection. Each table cell is one claim,
  checked on its own. A table asserts no relation: a relation is a claim with its own citation.
- [x] Distinguish missing evidence, partial answer, failed generation and unavailable verification.
  An unreachable judge must not produce a fully verified label. Revisit the current fallback
  explicitly and evaluate the impact before changing the existing short-answer behaviour. The
  fallback stays: unjudged claims still pass, and the answer shows « Vérification partielle ».
- [x] Support useful length by activity with token, evidence and processing budgets. Longer
  answers require more cited coverage rather than simply removing the current response limit.
  The general profile, whose one activity is explanation, allows more claims and words, each
  claim still cited and judged.
- [ ] Treat formulas and procedural instructions as factual content requiring support. A worked
  calculation needs explicit inputs and checked computation or an appropriately limited result.
  Procedure steps are cited claims. Formulas and worked calculations move to ANS-102.
- [ ] Resolve media references on the server to approved internal assets and locators. The model
  supplies no arbitrary embed URL, executable code, HTML or tool invocation. Moves to MED-102.
- [ ] Store schema and verification versions, source revisions and generation configuration for
  reproducibility. Preserve the existing distinction between search text and admissible evidence.
  Each claim keeps its source revision and the journal keeps the model. No schema version yet.
- [ ] Label interpretations and teaching proposals, with RECH-102 and PED-101.
- [x] Measure the general prompt on the developer-course set (`evaluation/dev/questions.json`).
  14 of 15 answered, 8 of 8 traps refused, 6 answers in blocks. Numbers and remaining defects in
  [evaluation](../../evaluation/README.md#reclasseur-et-génération).

## Frontend

Render blocks through application-owned templates. Cite individual steps, claims and comparison
cells where necessary. Keep exact source passages one action away. Use semantic tables and lists,
readable line lengths, explicit partial-result states and graceful fallback for unknown blocks.

Never stream unchecked model HTML into the DOM. Progress can stream immediately. Publish answer
blocks only after their validation and evidence checks, with cancellation and failure behaviour
defined by JOB-103. Do not rely on visual styling alone to distinguish a proposed activity.

- [ ] Stream blocks as they pass their checks. They render when the whole answer is complete.
