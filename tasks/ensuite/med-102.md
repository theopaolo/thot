## Backend

- [ ] Serve originals or compatible playback derivatives through authenticated resource routes.
  Validate every GET, HEAD and byte-range request against the resource's current permissions.
- [ ] Support bounded byte-range responses and correct content type/length so seeking does not
  require loading an entire recording into application memory. Handle invalid ranges safely.
- [ ] Map citations to a source revision, transcript segment and start/end time. Resolve references
  to internal media assets on the server. Revocation covers thumbnails, captions and derivatives.
- [ ] Qualify browser codec support and produce a standard playback derivative where necessary.
  Preserve the original and disclose conversion failures. Separate playback compatibility from
  transcription support.
- [ ] Serve captions generated from the selected transcript revision. Prevent caches or guessed
  paths from bypassing access after publication changes.

[HTTP range requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests)
describe the transfer mechanism needed for partial media delivery. The application still owns
authorisation and lifecycle rules on every request.

## Frontend and design

- [ ] Use native audio/video elements with accessible controls, captions, playback speed and a
  transcript beside or below the player. Avoid a custom player framework unless a measured need
  cannot be met with native controls.
- [ ] Clicking a timestamp citation seeks to the cited interval without autoplay. Highlight its
  transcript segment and show source title, revision and review state.
- [ ] Keep only the intended player active. Switching conversations cannot send controls or
  timestamp selection to the wrong source. Preserve per-source position within the session.
- [ ] Support keyboard navigation through transcript results and back to the citation. A transcript
  remains readable if playback fails. An unsupported codec displays a specific reason.
- [ ] Render compact media references in answers. Open the full player in the shared source panel
  rather than loading many video elements inside a long reply.

## Acceptance

- [ ] Seek to the beginning, middle and end of a recording through a citation.
- [ ] Unauthorised full and partial requests fail equally, including caption/thumbnail requests.
- [ ] Large-file playback does not allocate the complete file in server memory.
- [ ] Captions, keyboard controls and transcript-only fallback work at desktop and mobile widths.
- [ ] Validate playback in Helium and the supported mobile browser, recording any codec limitation.
