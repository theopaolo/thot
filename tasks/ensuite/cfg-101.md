## V1 scope

V1 moves values that the code fixes today, per profile or as constants, into settings an
administrator edits in the web administration. It adds only what a course outside applied arts
needs now: an
electrician course with a « Norme » field, a developer course with a software version, a training
centre that says « module ». The rest stays an operator setting or moves to the owners listed
under [Later](#later).

| Level | Setting | Read today by | Default |
| --- | --- | --- | --- |
| Instance | Name | page titles and brand, set by `thot instance --nom` | current value |
| Instance | Level label (« Classe », « Niveau ») | upload form, course form | preset term |
| Instance | Grouping label, singular and plural (« Séquence », « Thème ») | upload and edit forms, learner home, topic pages, source reader, teacher library | preset term |
| Instance | Default readers of a new deposit | upload form, CLI import | « Les enseignants et les élèves » |
| Subject | Upload fields: `CHAMPS` entries plus custom text, date or keyword fields | upload and edit forms, `validerInformations()`, learner reader | the preset's `informations` |

Decisions:

- Labels belong to the instance, not to each subject. A lycée says « séquence » in every subject
  and a training centre says « module » in every course. The learner home and the teacher library
  show several subjects on one page, where per-subject words would need a fallback rule. Revisit
  when one instance needs two vocabularies.
- A label is stored as a singular and a plural, without gender. Strings that put an article or an
  agreeing word next to the label change so they need the label alone: « Tes séquences » becomes
  « {pluriel} », « Ouvrir la séquence » becomes « Ouvrir » with the accessible name « Ouvrir
  {nom} », « Toutes les séquences » becomes « Tout », « Sans séquence » becomes « Autres
  documents », « Une question sur cette séquence ? » becomes « Une question sur {nom} ? ». Optional
  fields drop « (facultative) », since the upload form already marks required fields with « * ».
- Upload fields belong to each subject. The upload form already asks for the subject before
  showing its fields (« Choisir les champs »), so the list can follow the subject without a new step.
- Custom fields live in one instance catalogue: a generated stable key, a label and a type
  (« Texte », « Date », « Mots-clés »). Values stay in `sources.metadonnees` under that key and
  follow the validation of `validerInformations()`. Renaming keeps the key, so values survive. The
  type does not change after creation. Catalogue labels from `CHAMPS` stay fixed: a subject that
  needs another meaning creates a custom field.
- Removing a field from a subject hides it in forms and in the learner reader. Its stored values
  stay, and ticking the field again shows them. A custom field definition is deleted only while no
  source stores a value for it, the rule DOM-102 applies to subjects.
- In an arts subject, `date`, `artiste` and `mouvement` stay ticked, because arts enrichment and
  the artwork quiz read them.
- Learner pages keep tu in v1. Writing every learner string twice costs more than it buys before
  an adult-audience pilot shows whether impersonal wording is enough. The role nouns « élève »
  and « enseignant » appear about 120 times in views and routes and stay fixed in v1.
- Default readers apply to new deposits only. The upload form still shows the choice, and existing
  sources keep their readers. Personal mode hides this setting because a deposit there has one
  reader.
- The mode stays an operator choice made before accounts exist. Settings show it read-only.
- CLI import keeps its catalogue flags. Custom fields are filled in the web form in v1.

### Presets

The two profiles in `src/core/profils.ts` stay code presets. A preset fixes the processing that
was built or measured for it: PDF headings, caption, generation, judge and suggestion prompts,
arts enrichment and the artwork quiz. It also supplies the default labels and the default field
list. The unread `public` and `theme` keys become the label defaults, with a plural added for the
grouping label. `activites` stays unread until PED-101.

Settings store overrides only. An empty label or a subject whose fields were never saved falls
back to the preset. The pilot therefore looks the same after migration, and a profile change
before the first deposit changes the defaults without rewriting saved values. There is no plugin
system and no preset editor. A kind of course that needs different processing gets a new preset in
code and its own evaluation under EVAL-103.

### Measured prompts

No setting reaches a model. `profilSources()` picks the prompts from the profiles that the
retrieved sources captured at deposit. Labels, address, field names and field values stay out of every prompt. The arts prompts keep the SHA-256 fingerprints that
`tests/domaines_test.ts` checks against the ml4 measurements. Wording that a new audience needs,
such as adult trainees instead of « eleves de Terminale », is a code change to a preset. It reruns
the evaluation, as `docs/architecture.md` requires for any prompt change.

### Requirements kept and simplified

- Precedence stays operator environment, then instance, then subject. In v1 each setting lives at
  one level and falls back only to its preset, so no override chain needs resolving.
- The instance settings and each subject's field list carry an integer version for conflict
  detection. Renaming a custom field keeps the last save, like renaming a subject today. Jobs do not snapshot a configuration revision: no worker reads a v1
  setting, and jobs already read the profile stored on the source.
- There is no audit log: no v1 setting widens access to existing data or deletes any.
- Kept as written: typed validation, atomic save of a form, entered values preserved on error, no
  secrets in responses.
- Dropped until an owner needs them: stale-draft flags (PED-101 drafts), consequence previews for
  reindexing or migration, which no v1 setting triggers, a live preview of labels and an
  unsaved-change guard on forms of a few fields.

## Interface

Settings brief, following UX-201's design handoff acceptance. This task implements it.

Main action: change a setting, see where it shows, save it in one step.

### Place and navigation

Settings stay in the administration area, which administrators reach from the teacher rail and the
learner header. Primary navigation does not change. `/administration` gains a section navigation
in the `.onglets` pattern of the teacher library: « Instance » (`/administration`) and « Matières et
cours » (`/administration/domaines`). Other accounts get the existing refusal.

### Instance page

One `form.etroit` holds three fieldsets and one save:

1. « Identité » : « Nom de l'instance ». Below it, read-only: « Mode d'usage : partagé » or
   « personnel », with the aide « Choisi par l'opérateur avant la création des comptes. », then
   the instance identity code.
2. « Vocabulaire » : « Niveau », then « Regroupement, au singulier » and « Regroupement, au
   pluriel » side by side in `.deux`. Each input shows the preset term as placeholder, with an aide
   such as « Vide : Séquence, le terme du profil Arts appliqués. »
3. « Nouveaux dépôts » : radios « Lecteurs proposés par défaut » with the three existing reader
   labels. Aide: « S'applique aux prochains dépôts. Les ressources déposées gardent leurs
   lecteurs. » Hidden in personal mode.

The button row follows: « Enregistrer » (`.principal`) and « Annuler les modifications »
(`type="reset"`).

Under the form, read-only sections from today's page stay: « Profil d'import » with its name and
whether it can still change, linking to « Matières et cours », then « Traitement des documents et
des questions » with the providers.

### Matières et cours page

The existing page keeps its sections and gains three things:

- Under each subject row, a `<details>` « Champs du dépôt : n », in the same pattern as « Membres :
  n » under each course. It holds one form: fieldset « Champs prédéfinis » (one checkbox per
  `CHAMPS` entry), fieldset « Champs personnalisés », buttons « Enregistrer les champs » and
  « Annuler » (`type="reset"`), and the link « Voir le formulaire de dépôt » to
  `/prof/depot?matiere_id={id}`. Locked arts fields are ticked and disabled, with the aide
  « Utilisé par le quiz et les propositions de Thot. »
- A section « Champs personnalisés » after « Thèmes ». Each field uses the rename and delete row of
  `ligne()` in `src/app/vues/domaines.ts`, with a context such as « Date, 2 matières, 12
  ressources ». A creation form follows: « Nouveau champ » (text), « Type » (« Texte », « Date »,
  « Mots-clés »), « Créer le champ ».
- The profile change button gets the existing `data-confirmer` hook: « Changer le profil ? Les
  termes et les champs jamais modifiés prennent les valeurs du profil {nom}. »

### States

- Empty instance: no subject yet. Vocabulary placeholders show the general preset terms.
  « Champs personnalisés » reads « Aucun champ personnalisé. »
- Saved: the page reloads with `role="status"` « Réglages enregistrés. » above the form, focused
  through `tabindex="-1"`. Saving a subject's fields reopens its `<details>` with the status
  inside, as `?ouvert=` already does after a membership change.
- Validation error: HTTP 400, nothing saved. `role="alert"` « Rien n'a été enregistré. Corrigez
  les champs signalés. » appears above the form, each invalid field gets its `.erreur` line, every
  entered value is kept, and the first invalid field has `autofocus`. Messages: « 1 à 40
  caractères. », « Ce libellé existe déjà. »
- Conflicting edit: another administrator saved the same form after it loaded. HTTP 409, nothing
  saved. The alert reads « Ces réglages ont changé pendant votre saisie. Vos valeurs sont
  conservées. » The returned form keeps the entered values and carries the current version, so
  « Enregistrer » again saves them. Focus goes to the alert.
- Read-only: mode, profile once a resource exists, providers, instance identity, the type of an
  existing custom field and locked arts fields. They render as text or disabled inputs with the
  reason in an aide, not as controls that fail on save.
- Refused delete: « « Norme » est rempli sur 12 ressources. Retirez-le des matières pour le
  masquer. »
- Long labels: inputs enforce their maximum length. Long values wrap in previews, library tabs and
  headings. Nothing is cut with an ellipsis.
- Many items: each subject's fields sit in a closed `<details>`, so 50 subjects and 30 custom fields
  stay scannable. Checkboxes use the two-column `.deux` grid on desktop.

### Layout and focus

Desktop: forms in `.etroit` (44rem), labels above inputs, checkboxes in `.deux`. At 390 px:
one column, singular and plural stack, `.onglets` scrolls horizontally as in the library, button
rows wrap as `.barre`. Targets stay 44 px.

Section links carry `aria-current="page"`. Every input has a visible label, and aide lines are
tied to it with `aria-describedby`. Opening a `<details>` leaves focus on its summary. After a
server response, focus goes to the alert, the status message or the first invalid field.

### Content ranges

Instance name 1 to 100 characters, as today. Labels 1 to 40 characters, or empty for the preset
term. Custom field labels 1 to 60 characters, at most 30 custom fields per instance. Field values
120 characters, as today. Subjects 0 to about 50.

## Backend

- [ ] Store the instance settings on the `instance` row, the field list on each subject and custom
  field definitions in an instance catalogue. An empty value means the preset value.
- [ ] Give the instance settings and each subject's field list a version. A save sends the
  version it started from. A stale version saves nothing
  and returns the entered and current values.
- [ ] Save each form in one transaction. A validation error saves nothing and returns every entered
  value.
- [ ] Replace the `profil === "general"` and `profil === "arts-appliques"` label branches in the
  views with one lookup for labels and one for the field list of a subject. Sources without a
  subject use the preset list.
- [ ] Use the default readers in the upload form and in CLI import.
- [ ] Keep secrets, filesystem locations and provider URLs in operator configuration. Settings show
  provider availability read-only, as `/administration` does today.
- [ ] Keep prompts out of settings. The arts fingerprint test stays unchanged.

## Acceptance

- [ ] An administrator adds a subject and picks its upload fields, including a custom « Norme »
  text field, without editing files. The upload form and the learner reader show « Norme ».
- [ ] Setting the grouping label to « Module » and « Modules » changes the upload form, the learner
  home, topic pages, the reader and the library. Prompts and their fingerprints do not change.
- [ ] A new default reader applies to the next deposit and leaves existing sources unchanged.
- [ ] Removing a field hides it and keeps its values. Ticking it again shows them.
- [ ] Invalid settings and stale edits preserve user input and do not partially save.
- [ ] Network responses contain no credentials.
- [ ] Changing labels leaves existing citations, identifiers and access intact.
- [ ] `docs/vocabulaire.md` and `docs/architecture.md` describe the shipped settings.
