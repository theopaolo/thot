## Backend

- [x] Add a batch identity linking independently uploaded sources and their jobs. Accept shared
  course, subject and audience defaults with per-file overrides.
  Done: `sources.lot_id` and the shared form fields. Only the title is corrected per file.
- [x] Upload each file independently with bounded client concurrency and server quotas. Do not
  buffer an entire batch in one multipart request. Report bytes received separately from extraction.
  Done: one file per request, three at a time, size and count bounded by the server, "Reçu"
  distinct from the extraction state.
- [ ] Validate content type, actual bytes, permissions and size on the server. Enforce batch-wide
  counts and storage limits as well as per-file limits. Never trust the browser's MIME type.
  Done: per-file size, `MAX_LOT` files per batch, format read from the bytes. Left: a storage limit
  per batch.
- [x] Use checksums and an idempotency token to make retries safe. Show an accessible existing
  duplicate for review. Do not overwrite it or disclose a private source through duplicate detection.
- [ ] Keep successes when another file fails. Allow retry or cancellation of selected items,
  recover interrupted uploads and clean up abandoned temporary files.
  Done: retry of a single file. Left: cancellation (JOB-103), cleanup of abandoned `.partiel` files.
- [ ] Reuse ingestion jobs. Record per-file status and review warnings. Bulk publication checks
  each source independently and reports skipped items with their reason.
  Done: one job per file, state visible through `/prof?lot=`. Left: bulk publication.
- [x] Keep command-line folder imports consistent with the same metadata and validation rules.
  Folder selection in the browser is an enhancement with ordinary multi-file selection as fallback.
- [ ] For large media, qualify resumable file transfer before enabling the larger limits in
  MED-101. Choose a maintained resumable protocol implementation if full-file retries are untenable.

## Frontend and design

Provide select files and drag/drop into the same accessible flow. Show a compact editable list
with title, subject/course, format, size and status. Editing shared defaults must make individual
overrides visible. Users can leave the page after transfer and return to the batch's job list.

Review remains a separate action after processing. Show warnings and destination audiences before
publishing. Integrate the progress detail from [JOB-101](job-101.md). [JOB-103](job-103.md) may replace
polling, but it is not a prerequisite for a correct batch workflow.

## Acceptance

- [x] A mixed batch keeps valid files when another is corrupt, oversized or unsupported.
- [x] Refreshing or retrying cannot create unintended duplicate sources or processing charges.
- [ ] Cancellation cannot publish an unfinished resource. One failed file does not prevent review
  and publication of the successful files.
- [x] Keyboard-only upload and correction work on desktop and mobile layouts.
