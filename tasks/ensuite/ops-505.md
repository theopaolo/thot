## Apply at each increment of EVO-001

- [ ] Back up database and source files as a consistent set. Test restoration on an isolated copy
  before migrating the live pilot. Backups include source revisions, assets and required secrets,
  with access and expiry rules appropriate to the instance.
- [ ] Apply additive migrations first, then backfill source ownership, subject/course references,
  initial source revisions and legacy conversations. Preserve original identifiers and metadata.
  Report ambiguous account/course mappings for review rather than granting access by guesswork.
- [ ] Check a legacy database before migration 0007 runs. If its subjects would map to both import
  profiles, stop the upgrade and list those subjects. The operations guide explains how to split
  them into two instances.
- [ ] Keep compatibility readers for stored responses and old links during the transition. Verify
  citations against the exact pre-migration text, including Unicode offsets and image evidence.
- [ ] Build new indexes from authorised active revisions, verify them, then switch readers. A
  failed extraction or reindex cannot leave a partially published resource. Use [PRJ-201](prj-201.md)
  only if the measured rebuild requires full index-generation switching.
- [ ] Version parser, response and configuration changes so jobs and caches cannot reuse an
  incompatible result. Cache access never overrides current source permissions.
- [ ] Exercise cancellation, shutdown and queue recovery with the actual deployment process model.
  Add only qualified parser/transcription executables to explicit process permissions and the
  container. Keep the web server's process permissions narrower than the media worker's.
- [ ] Enable new formats and activities by capability after their acceptance checks. Incomplete
  processing services remain unavailable with a reason shown in settings.
- [ ] Coordinate deletion with [SRC-002](src-002.md). Source removal, conversation retention and
  account removal must cover derivatives, answers, jobs, caches and journals consistently.
- [ ] Define rollback per release. Stop/drain writers before restoring a snapshot. A rollback
  cannot promise to keep writes created after that snapshot without an explicit recovery method.
- [ ] Record job failures, queue times, model latency and extraction warnings without logging
  full private documents or credentials. Retain enough provenance to reproduce reported issues.

## Acceptance

- [ ] Dry-run migration on a copy of the existing pilot preserves accounts, sources, old messages
  and their citations, with any unresolved mappings listed before production rollout.
- [ ] A clean installation and an upgraded installation pass the same capability checks.
- [ ] Restore and rollback are demonstrated, including the treatment of post-backup writes.
- [ ] Deleting a source or conversation prevents in-flight jobs from recreating it.
- [ ] Each deployed increment meets its EVAL-103 and visual acceptance criteria.
