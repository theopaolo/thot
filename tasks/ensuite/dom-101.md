## Backend

- [x] Introduce stable subject and course identifiers within the instance. A course is a collection
  of resources with an optional audience and objective. Topics group resources within a course.
  Allow reuse of one source in several courses without copying its original or losing ownership.
- [x] Migrate existing subject values and sequences conservatively. Preserve original labels,
  metadata and source identifiers. Show unclassified materials rather than guessing a subject.
  Resolve courses with identical topic names by identifier, not by their displayed names.
- [x] Add general and applied-arts profiles. Profiles select existing typed metadata fields,
  audience vocabulary, extraction hints and available activities. Start with text, date, choice
  and tags where required. Do not build an arbitrary schema or prompt editor.
- [x] Make school year optional. Support level, author, source version, jurisdiction and applicable
  dates where a subject needs them. Separate an event date from publication and validity dates.
- [x] Remove Terminale, arts, artist and movement assumptions from generic answer, suggestion,
  support-judging and image-description prompts. Preserve the evidence requirements.
- [x] Move arts metadata enrichment, ATC heading cleanup and artwork quizzes into the arts profile.
  Profile changes do not silently relabel or regenerate existing reviewed content.
- [x] Apply profile selection consistently in web uploads, CLI imports, worker jobs, re-extraction
  and search context. Pass the required domain values into core rather than importing app config.
- [x] Treat source language separately from audience and subject. Evaluate French and English
  retrieval before exposing both as supported. Reindex when tokenisation changes. Mark unsupported
  languages clearly until the evaluation is adequate.

## Interface and design

Use subject and course filters with a visible scope. General profiles say resources and topics.
Subject-specific fields appear only when relevant. Keep list reading useful for text-heavy courses
and retain an image view for visual material. A resource can have multiple course affiliations
without acquiring conflicting publication permissions.

## Delivered

Subjects, courses and topics have stable identifiers. Existing subject values become subjects
and courses, with their sequences retained as topics. Source identifiers, original metadata,
reviewed content and historical uploader names survive migration. Unclassified resources stay
visible. A source can belong to several courses without copying files or changing its audiences.

Administrators configure the fixed general and applied-arts profiles, courses and topics in the
application or CLI. An instance has one profile, shared by its subjects and resources. The first
subject sets it, and it can change until the first resource is imported. Imports capture it.
Worker extraction, image descriptions, arts enrichment and re-extraction use that captured value.
Existing text cannot be replaced through
re-extraction if its citations would move. Source revisions remain the responsibility of ING-006.

General resources use neutral prompts and optional audience fields. Author, version, jurisdiction,
event/publication dates and validity dates are separate metadata. Lists, image display and visible
subject/course/topic filters use identifiers. Generic topic pages show resource lists. The arts
profile retains ATC extraction, reviewed artistic information, artwork quizzes and the answer,
judge, suggestion and caption prompts measured in ml4. Existing pilot
URLs remain usable. Course affiliation leaves publication controls on the source.

Source language is independent of subject and level. The unchanged French lexical search found
three of four synthetic morphology targets in French and one of four in English. English and
other languages are marked unsupported in uploads, extraction warnings and resource readers.
No bilingual model-quality claim or tokenisation change is introduced.
