## Design direction

Extend the existing interface using [the current stylesheet](../../static/style.css) and
[views](../../src/app/vues/). Keep Atkinson Hyperlegible, dense readable text and restrained
surfaces. No added letter spacing, uppercase titles, serif interface fonts or Tailwind. Give
library tables, long answers and media enough space without turning every item into a card.

The teacher operates a library and prepares teaching. The learner reads, asks and practises. An
account combining both gets a clear switch between these activities. Personal mode brings its
own materials and conversations together without classroom administration dominating navigation.

## Surface briefs to resolve before implementation

| Surface | Main action | Composition and interaction |
| --- | --- | --- |
| Library | Find, inspect or organise resources | Search and subject/course filters above a dense list, optional image view, selection toolbar |
| Bulk import | Submit and correct a group of files | File rows, shared defaults, individual overrides, per-file upload/processing/review states |
| Review | Check extraction and audience before publishing | Original or media alongside extracted content, visible differences and review status |
| Conversations | Continue an independent line of inquiry | Conversation list, active answer column, contextual source panel |
| Course comparison | Choose subjects and inspect connections | Visible scope, attributed findings, source links and a separate proposed-activity section |
| Settings | Change an instance or subject safely | Section navigation, compact forms, field preview and explicit save feedback |
| Study resources | Prepare, review and publish an activity | Objective, selected sources, editable draft, answer-key visibility and publication state |

Keep primary navigation close to the pilot's five-entry limit in [UI-101](ui-101.md). Put settings
in the account area and review queues inside the library. Resolve labels in the prototype instead
of adding one top-level item for every capability.

## Conversation behaviour

- [ ] Ship a conversation list with a new-conversation action, rename, archive, search and status.
  New replies continue while another conversation is open after JOB-103 ships.
- [ ] Show the active course/subject scope above the composer. Scope changes are explicit and
  apply to subsequent turns. Keep draft, scroll position and selected citation per conversation.
- [ ] Keep the answer column readable. A citation opens its source beside the answer on wide
  screens and in an accessible sheet on narrow screens.
- [ ] Add an optional two-conversation comparison layout after independent histories work. Keep
  it to two panes initially. Identify each composer and source panel, and collapse to one active
  conversation on mobile. This is a later layout step. Separate conversations with background
  replies are the first chat delivery.
- [ ] Preserve the reading position while updates arrive. Offer a new-content indicator when
  the user has scrolled up. Do not autoplay media or announce every streamed token.

## States and accessibility

Prototype empty instances, unavailable formats, partial upload failure, processing cancellation,
conflicting edits, unpublished material, missing evidence, revoked sources, failed diagrams and
long transcripts. Test short and long titles, mixed subject labels and large collections.

Keyboard users must be able to select files, inspect citations, switch conversations, seek media
and return focus after closing a panel. Provide a textual equivalent for each diagram and an
accessible mathematical representation. Use colour together with labels for job and review states.

Implemented surfaces receive desktop and mobile screenshots through chrome-devtools MCP using
Helium. Check focus, overflow, contrast, reduced motion and empty/error states. New rendering
dependencies load only on surfaces that need them. Update vocabulary with shipped labels.
