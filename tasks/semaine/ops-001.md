## Notes

L'image et le lancement des processus existent. [[inst-101]] couvre le provisionnement et
l'isolation des instances, mais n'a pas vérifié la construction ni l'exécution Docker.

Vérifié avec Docker Desktop (Node 26.11.1, utilisateur `node`, `--cap-drop=ALL`, volume neuf) :

- construction de l'image, démarrage sur un volume neuf : les 17 migrations s'appliquent, serveur
  et worker tournent sous le modèle de permissions.
- `thot ingest` de deux cours Markdown, `certifier --tout`, puis une question d'élève posée par
  HTTP après connexion : réponse vérifiée avec sa citation. Sans clé, le worker marque les
  suggestions comme traitées (aucun appel), ce qui garde l'appel de modèle à la seule question.
- `docker stop` rend la main en moins d'une seconde avec le code 0 : le lanceur attend la fin des
  deux processus. Un `SIGKILL` sur le worker ou sur le serveur arrête l'autre processus et le
  conteneur sort avec le code 1. Un `SIGTERM` sur le worker seul sort avec 0. Le serveur n'a pas de
  gestionnaire de `SIGTERM` : une requête en cours est coupée, les réponses interrompues
  reprennent au redémarrage.
- `thot backup` dans le conteneur en marche, restauration dans un volume neuf : la même réponse,
  la même citation et le même cookie de session. L'image crée `/sauvegardes` pour qu'un volume
  de sauvegardes neuf appartienne à `node`.
