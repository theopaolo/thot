## Notes

Les fichiers de `src/app/routes/` gardent 34 requêtes SQL. 18 recopient une règle d'accès, de
statut, d'établissement ou de compte : `FILTRE_ACCES`, `statut = 'certifiee'`, `school_id = ?`,
`ELEVES_GERES`, `LIENS_GERES`. `FILTRE_ACCES` ne contrôle pas le statut : une route élève qui
oublie `statut = 'certifiee'` montre une source pas encore relue. Les 16 autres remplissent une
seule page et peuvent rester dans leur route.

- Un module de lecture répond à « quelles sources ce lecteur peut lire, ou faire citer, dans ce
  périmètre » : `FILTRE_ACCES`, le statut certifié, l'établissement, les matières comparées. Les
  routes élève, `media.ts`, `perimetreRefuse` et `ideesPour` de `chat.ts` l'appellent.
- Les élèves gérés et les liens d'inscription de `prof-eleves.ts` passent dans `comptes.ts`.
- `FILTRE_ACCES` prend des paramètres nommés ([ADR 0008](../../docs/decisions/0008-sql-sans-orm.md)).

Fait quand aucune route n'écrit une règle d'accès, de statut ou de compte dans son SQL.
